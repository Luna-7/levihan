## 0. 北极星（不变）

**Fun hypothesis**：这游戏好玩的核心是**在近乎黑箱的局面里，赌下一张能不能对上**——不是解开谜题，是一次次下注。

| # | Pillar | 含义 |
|---|---|---|
| 1 | **未知优先** | 玩家永远不该知道"还有多少"和"下面压着什么" |
| 2 | **反馈只能物理，不能数字** | 允许"牌山肉眼在变矮"，禁止计数、百分比、进度条 |
| 3 | **每一步都是下注** | 拿牌的手感是"翻开"，不是"执行已知计划" |
| 4 | **归因必须模糊** | 失败后说不清是运气差还是自己蠢 |

### 0.1 v2 的三条修正（诚实记录）

| v2 的主张 | 处置 | 依据 |
|---|---|---|
| 「羊了个羊没有灰化，全靠物理遮挡」 | **撤回，你最初是对的** | 多个来源以相同措辞描述「观察第二层的灰色方块，和槽位对比找出能三消的组」。被压的牌**确实显示为灰色，而且认得出来**，玩家正是靠它提前规划 |
| 「必须加到 120 张」 | **撤回** | 多个游戏站一致指第二关约 **44 张**、**15 种图标**。这个量级撑不起 7 层深堆；120 是我从面积数学内部推的，不是原型事实 |
| 「exposure 低于 0.18 基本看不见，暗牌占 40%」 | **改为分级去饱和** | 原型玩家能认出第二层图案并据此规划。要做的是"看出层次"，不是"看得不全" |

**v2 仍然有效**：三层分区思路、frontier 约束、near-miss、反对清单、drift 破除对称。

## 1. 被压住的牌怎么显示（核心修正）

### 1.1 不要再"盖一层深色"

现状 `background: rgba(28,38,24,0.32)` 的方向是错的：

```
盖深色  = 把所有像素拉向同一个暗色
        → 色相差被压缩，明度差也被压缩
        → 整张糊掉，读出来是「这张坏了」
```

原型用的是去饱和：

```
去饱和  = 每个像素向"自己的亮度"靠拢
        → 明度结构完整保留，只是褪色
        → 一眼知道它被压着，但看得清是什么
```

### 1.2 规格：按 exposure 分级去饱和

替换 `TileFace` 里的 `rgba(28,38,24,0.32)` 深色叠加：

```css
.ex-2 { filter: grayscale(0.45) brightness(0.96); }  /* exposure 0.30 – 0.62 */
.ex-3 { filter: grayscale(0.68) brightness(0.94); }  /* exposure 0.10 – 0.30 */
.ex-4 { filter: grayscale(0.82) brightness(0.92); }  /* exposure < 0.10    */
```

再补一条：**去饱和要重度作用于方块底，图案层保留更多颜色**，让图案从底图里跳出来。

```
方块底（BLOCK_SPRITE_POS 那层）：取上表的满值
图案层（CARD_SPRITE_POS 那层）：取上表的 60%
```

〔待校准〕0.45 / 0.68 / 0.82 是手感起值。验收标准是：**第二层的图案要能一眼认出，并能和槽位里的牌做对比**——这正是原型玩家的核心玩法。

### 1.3 可点性的表达

仍然不用灰色做"禁用"标记，改用立体邀请，且**差异要小**：

| | 可点（exposure 至少 0.62） | 被压住 |
|---|---|---|
| Y 轴 | `translateY(-1px)` | 平贴 |
| 投影 | 重 | 轻 |
| 悬停 / 按下 | 抬起 3px + 提亮 | 无反应 |

### 1.4 三层分区（保留，参数重定）

| 层 | exposure | 呈现 | 可点 |
|---|---|---|---|
| 明牌层 | 至少 0.62 | 全彩 + 抬起 | 是 |
| 半掩层 | 0.10 – 0.62 | 分级去饱和，**认得出** | 否 |
| 盲盒柱 | 不适用 | 只露最上面一张，其余完全未知 | 仅最上一张 |

**48 张规模下深埋的暗牌自然很少**，未知的主要来源从"深埋"转移到 **盲盒柱**（约 11 张，占 23%）。这与原型一致：它的黑箱主要来自左右两摞加 7 槽压力，不是整屏失明。

### 1.5 frontier 约束（保留，且更重要了）

**任意时刻可点的牌数锁在 10–20 张。**

牌总数降到 48 后，这条成了主要难度旋钮。少于 10 无事可做，多于 20 玩家开始穷举优化、从下注退回解题。〔待校准〕需跑 200 局采样。

## 2. 规模：回到 48 张

### 2.1 为什么不是 120

多个来源指第二关约 44 张、15 种图标。在这个量级下，"平均 3.5 层深堆"数学上不成立。120 张是内部自洽的推导，不是原型复刻，此条作废。

### 2.2 为什么是 48 张（不是 44）

```
现有 CARD_TYPES 恰好 16 种图案
16 种 × 3 张 = 48 张 = 16 次消除
```

选它因为**天然整除，不用动现有的图案与雪碧图系统**，且落在 44–48 的原型量级内。

**注意理由与 v1 完全不同**：v1 说"每种 3 张便于追踪"已被你否决；现在的理由是"原型就是这个规模，48 刚好整除"。你担心的追踪问题由 Pillar 2（不给任何数字）保证，与每种发几张无关。

## 3. 布局

### 3.1 山头生成器（沿用，改浅）

```
x_0 = origin.x, y_0 = origin.y, layer = 1

for k = 1 .. layers.length - 1:
    [pc, pr] = layers[k-1]
    [cc, cr] = layers[k]
    x_k = x_{k-1} + (pc - cc) * CARD_W / 2 + drift.x
    y_k = y_{k-1} + (pr - cr) * CARD_H / 2 + drift.y
    layer = k + 1
```

`drift.x` 不能为 0，否则退回对称方阵。层数从 v2 的 7 层降到 **4 层**。

### 3.2 推荐配置（48 张）

```
主叠压区  origin (46, 34), drift (6, 6)
          layers = [[5,3],[4,3],[3,1],[1,1]]
          = 15 + 12 + 3 + 1 = 31 张，最高 4 层

左盲盒柱  origin (2, 110),   count 5, stepY 8, layer 10+i
右盲盒柱  origin (272, 110), count 6, stepY 8, layer 10+i

悬空辅助牌  6 张，分布在四角与中腰：
          (6,6) / (268,6) / (12,252) / (262,252) / (0,180) / (274,180)
          互不遮挡，也不与任何其他牌重叠

合计 31 + 11 + 6 = 48
```

**包围盒校核**（逐层算过）：

| 层 | x 范围 | y 范围 |
|---|---|---|
| L0 [5,3] | 46 – 276 | 34 – 196 |
| L1 [4,3] | 75 – 259 | 40 – 202 |
| L2 [3,1] | 104 – 242 | 100 – 154 |
| L3 [1,1] | 156 – 202 | 106 – 160 |

左右柱落在 2–48 与 272–318；六个悬空位已逐一核对，与主叠压区不相交。

### 3.3 悬空辅助牌（v3 新增，原型要素）

原型明确有"**左右两侧不需要消其他牌就能直接点**"的辅助牌。这是 v2 完全漏掉的结构，而且它和盲盒柱的角色**正好相反**：

| | 悬空辅助牌 | 盲盒柱 |
|---|---|---|
| 信息 | 完全已知 | 完全未知 |
| 什么时候用 | 想用就用 | 不敢轻易碰 |
| 承担的体验 | **救急资源**（可以攒着不用） | **风险**（抽了才知道） |

**没有它，玩家在 tray 快满时没有任何确定的逃生选项，near-miss 就造不出来。**它是战术层的必需品，不是装饰。

数量建议 4–6 张〔待校准〕。太少没有缓冲感，太多则 7 槽压力失效。

### 3.4 盲盒柱

| 参数 | 值 | rationale |
|---|---|---|
| stepY | 8 | 每张露 8px 上沿，够看见"这里有一叠"，不够看出是什么 |
| 单柱张数 | 5–6 | 两柱合计约 23% 的牌是真盲区 |
| layer | `10 + i` | 强制高于主叠压区，视觉上压住一切，读起来是独立的储备库 |

## 4. near-miss（保留）

**手段**：

1. **末期压力自然陡增**——牌越少 frontier 越小，第三个同花越可能埋在最深处
2. **配发时允许同花色聚簇**：约 20% 概率把某花色的 3 张塞进同一根盲盒柱的底层，这批要到终盘才露脸，那时 tray 往往已没余裕
3. **悬空辅助牌的消耗节奏**：它是唯一的确定出口，玩家会本能地留到最后——这正是 near-miss 的燃料。不需要额外设计，它天然发生

**诚实底线**（不变）：可以做"通关率极低"，但**不能铺"看似能解、实则必死"的局**。设一个真实目标通关率（建议 5%〔待校准〕）并明写"本关为极难关"。羊了个羊被骂的从来不是难，是被怀疑作弊的那一刻。

## 7. 验收与失败信号

**四条验收**：

1. **灰度可辨**（v3 最重要的一条）：把第二层某张牌截出来给没玩过的人看，他能说出这是什么图案。说不出就是 grayscale 压太重，回到 §1.2
2. **下注感**：录一段操作，看点之前有没有"犹豫加目视搜索"。一路秒点说明信息太多
3. **frontier 稳定**：全程随机抽 10 个时刻，可点牌数都应落在 10–20。超出范围回去调 §3.2 的层配置
4. **near-miss**：失败弹窗出现时，画面应剩不到 20 张且肉眼能看见"就差一组"

**Playtest 失败信号**：

| 信号 | 说明 |
|---|---|
| A. 玩家说"看不出第二层是什么" | grayscale 过重或图案层也糊了。**优先级最高**——观察第二层并据此规划是原型的核心玩法，这条坏了整个游戏就没了 |
| B. 玩家全程秒点不停顿 | 下注感没建立，在做体力活 |
| C. 玩家算出必胜套路并稳定通关 | frontier 超过 20，决策空间太大 |
| D. 玩家失败时说"它在耍我" | 触碰诚实底线，检查是否偷偷铺了必死局 |
| E. 玩家从不碰盲盒柱，也没用悬空牌救急 | 这两者作为"风险与救急"的对立没立起来，检查它们在视觉上是否足够独立，见 §3.3 |
